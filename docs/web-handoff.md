# 웹 GPT-6 개발 인계 — Music Producer Kit
작성일: 2026-09-19

## 사용자의 실제 목표
만들고 있는 제품은 Codex용 음악 제작 플러그인이다. 사용자가 일반적인 말로 요청하면 Ableton에서 음악을 만들거나 지정한 부분만 수정하고, 보호 대상은 유지하며, 편집 가능한 프로젝트를 저장·재열기할 수 있어야 한다. 완곡과 좁은 부분 수정 모두 유효하다. 사용자가 매번 이론 용어·셋업 명령·내부 스크립트를 지정할 필요가 없어야 한다.

이번 4마디 제작은 실제 PC 연결 검증이었다. 테스트 곡 자체가 제품의 최종 산출물은 아니다. 로컬 에이전트가 “완료”라고 보고한 범위는 그 검증이며, 설치된 배포 플러그인에서 자연어 요청부터 저장된 결과까지 반복 재현되는 제품 흐름은 아직 완료 판정을 내리지 않았다. 사용자가 이 차이를 지적했고, 이제 플러그인 개발로 초점을 돌려야 한다.

- marketplace, portable root plugin.json, 패키지 검사/ZIP 생성, unittest, 21개 정의된 행동 시나리오.

## 실제 Windows PC에서 검증한 사실
- 기존 Codex 앱과 Live 설치를 조사했고 Ableton MCP는 없었다. 사용자가 새 구현의 시험 설치를 승인했으며, 문제 발생 시 이번에 추가한 연결 소프트웨어/설정만 제거한다는 조건이 있다.
- 선택/설치한 구현: nicholasbien/ableton-mcp-pro, commit 6ae148de18c8042df041b95c6e830bcdf22be526. 소스/라이선스를 검토하고 고정했다. 이 설치본과 컴퓨터별 설정은 공개 저장소에 들어 있지 않다.
- 실제 Live 12 Suite 12.4.6. 시작 때는 12.4.5였으며 기존 자동 업데이트 후 버전이 바뀌었다. 에이전트가 Live 업그레이드나 관리자 설정을 변경하지 않았다. 사용자가 기존 관리자 실행 설정을 직접 해제했다.
- 기존 번들 Python 3.12.14로 서버와 진단 환경을 분리했다. 서버는 mcp[cli] 1.30.0의 FastMCP, 프로젝트 진단은 공식 SDK 2.2.0을 사용한다. 시스템 Python이나 저장소 의존성 고정값을 변경하지 않았다.
- Live User Library Remote Script 하나와 빈 Control Surface 슬롯 하나, Codex ableton_live stdio 항목 하나만 추가했다. Live 측은 127.0.0.1:9877 TCP이며 HTTP MCP URL이 아니다. 공개 포트·방화벽 예외는 추가하지 않았다.
- 실제 tools/list에서 78개 스키마를 받았다. 실제 Codex 데스크톱 내장 core 0.155.0-alpha.9.2의 새 임시 실행에서 get_session_info를 정확히 1회 호출해 정상 응답을 확인했다.
- 기존 PATH CLI 0.145.0은 기본 모델 버전 오류로 실패했다. 이미 설치된 내장 core를 사용해 해결했고 모델 변경·CLI 업그레이드는 하지 않았다.
- 이미 열린 로컬 작업의 도구 목록에는 새 서버가 즉시 추가되지 않았다. 쓰기 검증은 같은 설치 서버에 공식 MCP Python SDK로 연결한 비공개 보조 스크립트로 수행했다. “설치된 producer 스킬이 네이티브 MCP 도구로 전 과정을 수행했다”는 증거로 바꾸어 말하면 안 된다.
- 사용자가 기존 미저장 Untitled를 폐기해도 된다고 승인했다. 새 테스트 Set으로 전환하고, 새 Set에 다시 나타난 기본 마이크 템플릿의 빈 트랙만 교체했다. 기존 저장된 곡은 변경하지 않았다.
- harmony-study.json 그대로 96 BPM, 4/4, 4마디를 Arrangement의 편집 가능한 MIDI로 만들었다. Harmony는 16음표짜리 클립 하나, Bass는 마디별 클립 네 개다. 실제 조회한 Live 기본 Electric/Operator를 사용했다. 샘플은 사용하지 않았다.
- Bass의 Arrangement beat [4,8)만 변경했다. 원래 pitch45 4박을 pitch45 2박 + pitch52 2박으로 교체했다. 마디별 클립 구조를 이용해 해당 클립만 삭제·재생성했고 인덱스를 다시 조회했다.
- Live UI 자동화로 baseline.als와 revised.als를 별도 저장했다. 두 파일을 실제로 차례로 다시 열고 각각 15개 MCP 읽기를 수행했으며 저장 전 상태와 완전히 일치했다. 수정본의 두 음을 Live 피아노롤에서 확인했다.
- 저장된 .als gzip/XML과 실제 읽기 결과를 비교한 28개 검사 통과. Harmony 전체, Bass 1·3·4마디, 장치·믹서·라우팅·오토메이션·마스터 등 보호 내용은 동일했다. 차이는 요청한 클립의 음표/재생성 ID와 재생 위치뿐이었다.
- 로컬 tools/check.py 통과. unittest 110개 실행, 109통과/심볼릭 링크 권한 관련 1skip. 초기 의존성/임시 디렉터리 ACL 실패는 해결 후 성공과 구별해 기록했다. 이번 세션에서 새 원격 CI는 실행하지 않았다.

## 아직 증명하지 않은 것과 구현상 주의점
- 배포 플러그인 설치·진입 스킬 활성화부터 자연어 제작/부분 수정/저장까지의 전체 사용자 흐름을 같은 실행에서 검증하지 않았다.
- 이 backend에 새 Set·저장·열기 MCP 도구는 없다. 이번에는 호스트의 실제 Windows UI 자동화로 완료했다. 없는 MCP 함수를 만들거나, UI 자동화를 사용자 수동 작업으로 잘못 기록하지 말 것.
- 전체 78개 도구, 청취·렌더링·음악 품질, 가사/보컬의 원어민 검토, 정의된 21개 행동 시나리오는 실행 검증하지 않았다.
- 기존 복잡한 곡, 경계를 가로지르는 음표/페달, MPE/probability/release velocity의 안전한 수정으로 이번 결과를 일반화하지 말 것. MCP 음표 조회는 pitch/start_time/duration/velocity/mute에 한정된다. 저장 XML 비교는 이번 파일의 보호 내용에 대한 보완 증거다.
- 일부 setter 응답은 이전 값을 보여 주거나 오류를 문자열로 반환할 수 있다. 쓰기 후 실제 상태를 다시 읽어야 한다. 타임아웃 후 대기 중 쓰기가 실행될 수 있으므로 재시도 전에 Live를 읽는다.
- Remote Script의 schedule_message(0)/AssertionError fallback 설계 약점은 소스 검토에서 관찰했다. 실제 설치된 Live 스케줄러에서는 그 assertion이 활성화되어 있지 않았고 작업이 큐에 들어갔다. 확인되지 않은 결함을 확정하거나 모든 Live 버전의 안전성으로 일반화하지 말 것.
- 기존 문서/manifest에 “미검증”, “후보 미선정” 등 오래된 일반 문구가 남을 수 있다. docs/STATUS.md의 최신 실제 관측과 제품 전체 검증 범위를 나누어 정리해야 한다. 검사 스크립트의 고정 false 플래그를 true로 바꾸는 것으로 런타임 검증을 대신하지 말 것.

## 이어서 요청하는 개발 작업
현재 트리부터 확인하고, 이번 로컬 성공을 사용자가 설치해서 쓸 플러그인의 반복 가능한 작업 흐름으로 연결하라. 문서나 계획만 늘리는 것으로 끝내지 말고 필요한 최소 변경을 실제 구현하고 검증하라.

1. 설치/활성화, MCP 연결, 음악 작업, 저장/재열기, 검증 중 기존 스킬 지침으로 충분한 부분과 실제 도우미/호스트 기능이 필요한 부분을 구분한다. CLI 버전·MCP 새 세션·Windows UI 의존성을 명확히 한다.
2. 먼저 한 경로를 완성한다: 설치된 music-producer 호출 → 실제 현재 Set/도구 조회 → 승인된 새 4마디 → “베이스 두 번째 마디만 바꿔” → 보호 영역 비교 → 저장/재열기 확인. 임시 개인 스크립트나 개발자가 외워야 하는 명령에 의존하는 구간을 없애거나 플러그인의 명시적 기능으로 정리한다.
3. 기존 MCP 구현을 재사용한다. 필요 증거 없이 서버를 새로 만들거나 여러 backend, 범용 추상화, 자동 설치/자동 복구를 추가하지 않는다. 비공개 보조 스크립트의 존재만으로 복사 가능한 공개 코드가 있다고 가정하지 말 것.
4. 개인 경로나 곡을 하드코딩하지 않는 인터페이스, 승인된 대상 식별, 변경 범위/보호 항목 검증, 재열기 증거를 다룬다. 범위를 좁게 시작하되 새 4마디 생성만 가능한 제품으로 축소하지 말 것.
5. 이 구현에 필요한 의미 있는 검사와 실제 모델 시나리오를 실행한다. 패키지 테스트 성공과 모델/DAW 성공을 구별한다. 실제 PC 기능이 필요하면 로컬 Codex에 줄 구체적인 검증 요청과 기대 증거를 작성한다.
6. 웹 환경에서 실제 사용자 PC의 Live를 조작할 수 없는 경우 코드·패키지 작업까지 완료하고 로컬 실행만 정확히 분리해 넘긴다. 실행하지 않은 단계를 성공이라고 보고하거나 이미 검증한 초기 인터뷰/설치를 반복하지 않는다.

## 고정된 사용자 요구와 금지사항
- 전체 곡 제작과 지정 부분 수정 모두 지원. 승인된 나머지 재료를 보존.
- 한국어·영어·일본어 가사/보컬 및 혼합, 연주곡. 영구 취향/장르/보컬/언어를 다시 인터뷰하지 않음.
- 중국 특화 제작 자료는 작업 라이브러리와 배포본에서 제거된 상태를 유지. 일반 중국어 음악이론·일본어 한자는 유용한 범위로 유지. 숨긴 원본·복구/감사 모드·자동 소스 다운로드는 만들지 않음.
- Mido/SoundFile/공식 MCP SDK 재사용. MIDI 파일을 Live Set으로 부르지 않음.
- 샘플 구매·Splice 크레딧 사용·외부 오디오/프로젝트 업로드·계정 변경은 별도 명시 승인 없이 하지 않음.
- 개인 경로·자격증명·유료 샘플·미공개 곡·실제 호출 로그는 공개 저장소에 넣지 않음.
- 기존 LICENSE/NOTICE 보존. 사용자 요구 없이 호환 계층·마이그레이션·두 번째 진입 스킬·불필요한 의존성을 추가하지 않음.

## 이번 첨부물의 범위
이 문서와 소스 ZIP은 전달용으로 로컬에 준비한 것이다. 웹 대화에 자동 업로드하거나 공유 링크를 만들지 않았다. ZIP에는 Git 메타데이터/이력, PC 설정, 별도 설치 서버/가상환경, 사적인 .als, 실제 MCP 보고서·로그가 없다. 상세 로컬 증거는 소유자의 비공개 작업 폴더에 보존되어 있다. 웹에서 그 폴더에 접근할 수 있다고 가정하지 말 것.
