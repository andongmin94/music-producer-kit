# 다음 작업: 공식 경로의 실제 계약 확인

상태: 0.7.1에서 옛 개인 MCP 전용 경로를 제거했다. 공식 기반 Live 연결은 아직 구현하지 않았다.
이 작업은 취향 인터뷰나 이전 MCP 재설치가 아니다. 현재 필요한 자료와 승인만 확인한다.

## 웹에서 확인한 사실 — 2026-09-19

| 항목 | 확인 결과와 근거 |
|---|---|
| 제조사 SDK | [공식 소개](https://ableton.github.io/extensions-sdk/)는 JS/TS 확장 개발 도구를 제공한다. 완제품 MCP 서버 제공을 이 자료에서 확인하지 못했다. |
| 호환 조건 | [공식 FAQ](https://help.ableton.com/hc/en-us/articles/27303428331420-Ableton-Extensions-FAQ)는 Live 12 Suite **Beta** 12.4.5 이상을 명시한다. 일반 출시판 12.4.6이라는 숫자만으로 지원을 확정하지 않는다. |
| 실행 방식 | 공식 FAQ는 문맥 메뉴에서 실행하는 일회성 작업을 설명한다. 실시간 신호 처리 제한을 일반 오프라인 편집 불가로 확대 해석하지 않는다. |
| 정확한 API | 공식 SDK 페이지의 다운로드/문서 링크는 이 웹 환경에서 Centercode 세션 오류/로그인으로 연결됐다. 타입·예제·라이선스 원문은 아직 확인하지 못했다. |
| Codex 연결 | [공식 Codex 문서](https://developers.openai.com/codex/mcp/)는 MCP 클라이언트 연결을 설명한다. 제조사 SDK 자체가 MCP 서버라는 뜻은 아니다. |

다른 개인 MCP나 비공식 SDK 래퍼를 공식 제품인 것처럼 가져오지 않는다.
우리가 제조사 SDK로 만드는 코드 역시 우리 코드이며 Ableton이 배포·보증한 MCP가 아니다.

## 로컬 Codex가 확인할 최소 항목

먼저 이미 설치되거나 사용자가 제공한 공식 자료와 현재 앱의 버전/에디션/릴리스 채널을 읽기 전용으로 확인한다.
이미 로컬에 SDK가 있다면 문서·타입·공식 예제·라이선스를 읽되 설치 스크립트를 자동 실행하지 않는다.
없다면 SDK와 문서를 소유자 계정으로 확보해야 한다는 한 가지 요청만 남긴다. 비밀번호·토큰을 요구하거나 계정 가입·Beta 설치를 대신 승인하지 않는다.
SDK를 받는 것과 Live Beta를 설치하는 것은 별도 단계다. 정확한 설치 필요성과 변경 범위를 먼저 설명한다.

개발에 필요한 결과는 다음 여섯 가지다. 각 행에 **실제 API 심볼/타입 위치 또는 확인 불가**를 적고 추측은 넣지 않는다.

| 확인할 계약 | 필요한 판단 |
|---|---|
| 실행 진입점 | Codex가 승인된 확장을 호출하고 결과를 받을 공식 경로가 있는가? 문맥 메뉴만 있는가? |
| 현재 Set 식별 | 사용자가 의도한 Set, 트랙/클립과 변경 상태를 안정적으로 식별할 수 있는가? |
| 생성·음표 수정 | Arrangement 작성, 음표 단위 갱신, 표현/확률/자동화 등 보호 항목을 어떻게 보존하는가? |
| 장치·로컬 샘플 | 실제 설치된 장치 탐색과 샘플 로딩이 어느 API로 가능한가? |
| 저장·새로 열기 | API가 있는지, 없으면 승인된 호스트 UI 작업이 필요한지. 없다고 미리 결론 내리지 않는다. |
| 배포·권한 | SDK/산출물 재배포 조건, 요구 버전, 필요한 승인과 권한은 무엇인가? |

계약이 확보되면 한 경로만 작게 구현한다. 확인되지 않은 서버, 병렬 backend, 이전 개인 MCP fallback은 만들지 않는다.
자료 확보 전에는 추정 API로 스켈레톤 코드를 늘리지 않는다. 실제 PC 증거는 비공개로 두고 공유 가능한 요약만 되돌린다.

## 로컬 Codex에 전달할 요청

```text
최신 main의 docs/STATUS.md, docs/web-handoff.md와
이 docs/official-path-review.md를 읽어.

이전 개인 MCP는 제거한 상태를 유지해. 설치부터 다시 하지 마.
현재 Live의 에디션/릴리스 채널과 이미 확보한 공식 Extensions SDK 자료를
읽기 전용으로 확인하고, 위 여섯 항목을 실제 문서/타입/공식 예제로 대조해.
자료가 없으면 공식 SDK·문서 확보에 필요한 소유자 작업만 알려줘.
Beta 설치, 계정/설정 변경, 패키지 설치는 승인 없이 하지 마.

음악 취향이나 한영일 범위를 다시 묻지 마.
기존 곡은 저장·닫기·수정하지 말고, 비공개 진단 결과를 남겨.
지원 API와 부족한 연결 부분을 구분해, 한 경로를 구현할 수 있는
개인정보 없는 인계 요약만 작성해. SDK 전문은 재배포 권한 확인 전 올리지 마.
```

## 그 뒤의 완료 기준

[설치 흐름 검증](installed-flow-acceptance.md)은 새 경로 구현과 필요한 승인 이후 실행한다.
스킬 활성화 → 자연어 새 작업 → 지정 부분 수정 → 보호 영역 비교 → 저장·재열기 → 연속 수정의 증거가 있어야 한다.
기존 파일 검사 성공이나 옛 PC 실험만으로 이 기준을 통과했다고 표시하지 않는다.
