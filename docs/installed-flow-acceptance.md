# 로컬 Codex에 넘길 검증: 설치된 0.7.0 전체 흐름만

## 이번에 다시 하지 않을 것

연결 설치, 서버 후보 선정, 취향/언어 인터뷰, 이전 4마디 PC 실험을 처음부터 반복하지 않는다.
2026-09-19 인계에서 확인한 연결은 유지한다. 이번 검증 대상은 **배포본을 설치한 새 Codex 세션에서 자연어 → 기존 네이티브 MCP → 번들 도우미 → 호스트 UI 저장/열기**가 이어지는지다.
이전 비공개 SDK 쓰기 스크립트를 사용하면 이번 설치형 흐름의 통과 증거로 인정하지 않는다.

## 로컬 개발 Codex가 준비할 것

이 패키지를 기존 marketplace 경로에서 갱신/설치하고, 새 사용자 세션에 실제 설치된 music-producer가 노출되는지 확인한다. 사용자의 정상 모델을 지원한 데스크톱 내장 core를 사용하며 PATH CLI를 임의 업그레이드하거나 모델을 바꾸지 않는다.
설치된 SKILL.md의 실제 경로, 파일 해시, manifest 0.7.0을 비공개로 기록한다. 개발 checkout의 문서를 대신 읽거나 프롬프트에 본문을 붙여 넣어 설치 검증을 대체하지 않는다.
MCP 연결은 기존 ableton_live 한 개를 재사용한다. 서버 MCP 1.30.0과 진단 SDK 2.2.0 환경을 섞지 않는다. 이미 열려 있던 옛 세션이 도구를 못 보는 문제는 새 세션에서 확인한다.
기존 미저장 작업이 있다면 폐기 승인을 재사용하지 말고 현재 작업을 보호한다. 테스트용 새 Set과 비공개 폴더만 승인 범위로 삼는다.

## 동일한 설치 사용자 세션에서 순서대로 요청

첫 프롬프트에서 플러그인을 선택한 뒤 다음처럼 요청한다. 파일 형식·스크립트·MCP 명령을 사용자가 지정하지 않아도 스킬이 알아서 처리해야 한다.

> 새 테스트 프로젝트에 차분한 4마디 반주를 만들어줘. 피아노 화음과 베이스를 따로 편집할 수 있게 하고 저장해줘. 기존 곡은 그대로 둬.

> 베이스 두 번째 마디만 두 음으로 바꿔줘. 화음과 나머지 마디는 그대로 두고 새 버전으로 저장해.

> 방금 저장한 원본과 수정본을 차례로 다시 열어서 수정한 부분 외에는 그대로인지 확인해.

이후 같은 수정본에서 다른 마디를 한 번 더 바꿔, 새 receipt를 이어 사용하는지 확인한다.
별도 세션에서 "가사만 한국어 4줄 써줘. DAW는 건드리지 마"를 요청해 불필요한 연결/편집이 발동하지 않는지도 확인한다.

## 기대하는 증거

| 영역 | 실제로 남길 것 |
|---|---|
| 설치·진입 | 설치된 패키지 버전·SKILL 해시·읽은 실제 경로. 개발본 중복 활성화 없음 |
| 네이티브 경로 | 같은 사용자 세션의 MCP 호출 기록. 어떤 도구가 실제로 실행됐는지; helper가 대신 직접 연결한 기록이 아님 |
| 제작 | 번들 live_workflow.py가 만든 계획, actual bindings와 capture, verify-created receipt |
| 부분 수정 | 직전 전체 checkpoint, edit plan, 삭제 후 absence 검증, 생성 후 verify-edit 및 갱신 receipt |
| 보호 범위 | note 비교 외에 장치/믹서/라우팅 포함 readback 비교; 저장 XML 전체 차이 목록과 변경 허용 이유 |
| 저장·재열기 | 실제 Windows UI 자동화 이벤트·저장 파일 SHA256·새로 수집한 각 파일의 native readbacks |
| 결과 | 각 단계 PASS/FAIL/BLOCKED와 근거. 렌더·청취는 하지 않았다면 별도 NOT RUN |

번들 `live_set_diff.py`는 저장 XML을 수정하지 않는다. 이 함수의 합성 fixture 검사와 실 .als 호환성을 구분해서, 이번 파일로 실제 출력과 경로를 확인한다.
MCP에 보이지 않는 MPE·probability·release velocity·클립 자동화가 있는 곡으로 안전성을 일반화하지 않는다. 이번 clip 재생성 경로는 스킬이 새로 만든, 그 뒤 숨은 변경이 없는 기본 음표 클립만 대상으로 한다.
`verify-reopen`의 JSON 일치만으로 열기 성공을 기록하지 않는다. UI 열기 이벤트와 파일 식별이 함께 필요하다.

## 실패하면

어느 단계에서 막혔는지와 실제 오류만 기록한다. UI 도구가 없으면 그 구간만 BLOCKED이다. 테스트를 통과시키려고 사설 SDK writer를 만들거나 입력 규격·비교 조건을 약화시키지 않는다.
setter 오류/타임아웃 후에는 Live 현재 상태부터 읽는다. 대기 중 쓰기가 나중에 실행될 수 있으므로 같은 삭제/생성을 재전송하지 않는다.
자동 재설치·추가 권한·구매·크레딧·업로드는 없다. 문제가 발견되면 원래 승인된 시험 연결 소프트웨어/설정에 한해서만 제거 범위를 논의한다.

## 웹 개발로 돌려줄 것

개인 경로/곡/샘플/토큰을 제외한 단계별 결과와 재현 가능한 오류만 돌려준다. 새 실제 호출 로그와 .als 원본을 공개 레포에 커밋하지 않는다.
현재 웹 실행 환경에는 Codex 실행 파일·모델 인증·사용자 PC/UI가 없어서 실제 모델 시나리오와 이 설치형 실행은 수행하지 못했다. 합성 데이터/패키지 검사를 실제 모델 평가로 바꿔 적지 않는다.
